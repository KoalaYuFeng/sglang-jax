# DeepSeek-V4-Flash v5p accuracy baseline and release checks — 2026-09-11

This is a task-accuracy-validated integration baseline, not a claim of complete
official-runtime numerical equivalence or production/SLA acceptance.
Branch: `integration/deepseek-v4`, built on `270dfcbd`. The commit containing
this report publishes the previously uncommitted numerical fixes and evidence.

## Exact runtime setting

- Official **Instruct** checkpoint `deepseek-ai/DeepSeek-V4-Flash`, revision
  `60d8d70770c6776ff598c94bb586a859a38244f1`, complete 43 layers.
- One v5p-8 VM, **four physical TPU v5p chips**, TP4 / EP4 / DP1.
- Original packed FP4/FP8/block scales remain stored; online dequantization,
  BF16 activations and FP32 accumulations. No whole-model BF16 expansion.
- SGLang-JAX HTTP service: context 8192, page 128, global chunked prefill 128,
  maximum four running requests and 33,280 KV-token capacity; hybrid SWA memory
  disabled, static memory fraction 0.85, server seed 42.
- Explicit execution overrides: mHC/HCA/CSA `pallas`, MoE `gmm_tuned`,
  attention TP and batched CSA decode enabled, FP8 `gmm`, fused normalization,
  merged projections and fused `wo_a` enabled. Defaults are not assumed to
  enable all these options.
- Runtime fingerprint for GPQA, GSM8K and the new short HTTP benchmark:
  `1a83e8ac9731d885187c80ecf25834b6782528c3a002f4b5a994570dfdcd60b3`.
  All 730 non-generated runtime source files match the GPQA disk snapshot.
  Its additional `_version.py` is generated by the remote build, not tracked
  or copied over the local source tree. The private GPQA archive retains it.
- TPU environment: JAX/jaxlib 0.11.1, libtpu 0.0.46.1. Full server command,
  configuration snapshots, tokenizer/encoder hashes and source manifests are
  retained in private experiment evidence, not inferred from a branch name.

## Performance provenance

The [historical 4K/8K ModelWorker matrix](deepseek_v4_8320_validation_profile.md)
is retained, including B1/4/8/16/32, 32 outputs, TTFT/TPOT, HBM snapshots and
profiles. It used runtime fingerprint
`2543e8b0e98fc56658912cd2d14f05e4d4ae4e00cc961f07bc150744070e0c0f`,
**not the latest RoPE/index-pooling numerical baseline**. It also used a
diagnostic total-context guard of 8320 and 128 prefill tokens *per request*
per ModelWorker call. Do not present it as current HTTP performance.

The new short same-source HTTP check uses unmodified `sgl_jax.bench_serving`,
128/1024 input tokens, 32 forced outputs, concurrency 1/4, no prefix-cache hits,
at least two warmups and three compile-free measured waves. Its input/output
throughput divides by **whole request-batch wall time**, not isolated prefill
or decode time. TTFT/TPOT include scheduling and transport. It is a small
finite-batch performance check, not a sustained-load or high-concurrency SLA.

Completed results below are the median of three measured waves per case.
TTFT/TPOT are per-wave request means before taking that median; throughput is
the aggregate across all requests. All cases generate exactly 32 output tokens.

## Numerical changes and regression status

The published runtime changes are limited to the existing V4/kernel scope:

1. Rank-ordered FP32 EP reduction in legacy and GMM MoE paths, with independent
   cancellation/request-layout tests. Packed weights and local GEMM unchanged.
2. Immutable host FP32 RoPE coefficients with official rounding order; dynamic
   positions still multiply on device. No host callback or PyTorch runtime
   dependency is introduced.
3. Compensated FP32 CSA index pooling and range-reduced exponentials, limited
   to the V4 index emitter. Main KV compression, state ownership and legacy
   numerical modes are unchanged.

No core scheduler algorithm was changed during this release work.

Validation performed before publication:

- Final local independent CPU suite: **194 passed, 5 skipped**, including
  11 short-benchmark metric/log-audit tests. The initial larger
  local collection lacked Flax; this environment issue is retained in evidence,
  not counted as a numerical failure or silently repaired by changing packages.
- Remote **CPU-only** framework suite after test-oracle alignment:
  **47 passed, 58 skipped**. TPU-specific cases were skipped in this CPU run;
  this is not a new full TPU kernel regression. Five new independent RoPE
  oracle tests also passed locally (included in the remote count, not additive).
- Static Ruff checks and whitespace checks passed for publication scope.

The first remote CPU framework run had **6 failed / 36 passed / 58 skipped**.
The frozen bring-up reference still constructs RoPE powers inside XLA, unlike
the corrected native host-FP32 path. An isolated in-memory rollback of *only*
the native RoPE phase made all eight related tests pass. The final paging tests
instead use a **test-scoped independent official PyTorch FP32 coefficient
recipe** for the reference, checked against frozen official integer bits.
All bitwise paging/output assertions remain. Neither tolerances nor production
kernels nor the historical reference file were changed to obtain the final pass.
Original failures, legacy-phase control and final JUnit receipts are retained.

Existing [CPU/TPU distribution differences](deepseek_v4_endtoend_accuracy_20260911.md)
and the earlier compressor matrix's 15/18 result remain documented. Task scores
do not erase those findings. Full current-source 43-layer long-context,
multi-request numerical/stress regressions remain separate acceptance work.

## Reproduction entry points

- `scripts/prepare_deepseek_v4_gsm8k_data.py --output PRIVATE_NEW_DIR` obtains
  the exact original dataset, checks its fixed hash and writes source metadata.
- `scripts/evaluate_deepseek_v4_gsm8k.py prepare --output PRIVATE_NEW_DIR
  --reference-protocol GPQA_PROTOCOL --tokenizer PINNED_TOKENIZER_DIR` freezes
  the input IDs, sample and scoring settings. The reference protocol supplies
  the checkpoint path and the already verified tokenizer/encoder hashes.
- `scripts/evaluate_deepseek_v4_gsm8k.py run --output PRIVATE_NEW_DIR
  --server-receipt OWNED_SERVER_RECEIPT --base-url http://127.0.0.1:30126`
  verifies the exact owned PID/command/configuration before inference.
- `scripts/evaluate_deepseek_v4_gsm8k.py audit --output PRIVATE_NEW_DIR`
  recomputes all scores and hashes. Preserve the runner and atomic-helper bytes
  used to create the protocol; auditing refuses changed script/input hashes.
- `scripts/benchmark_deepseek_v4_release.py --help` lists the existing-service,
  completed-accuracy and frozen dataset receipts required for the short check.
  It does not launch, restart, reconfigure or replace the model service.
- `scripts/audit_deepseek_v4_release_benchmark.py --output PRIVATE_PERF_DIR`
  checks the completed short-benchmark evidence and recomputes its summary.

The existing GPQA evaluator and historical accuracy/profile diagnostic scripts
are published alongside these additions. Private startup/SSH credentials and
raw evidence remain excluded from Git.
